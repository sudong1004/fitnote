# 02. 기능 명세서

요구사항 번호(`FR-…`)는 [01 요구사항 정의서](01-requirements.md) 와 같다. "오류" 칸의 문구는 화면에 그대로
보이는 문구다. 서버가 모든 입력을 다시 검사하며, 화면의 `maxLength`·`required` 는 편의일 뿐이다.

## 1. 계정·인증

### 1-1. 가입 (FR-AUTH-01~03)

| 항목 | 규칙 |
| --- | --- |
| 입력 | 가입 유형(회원/트레이너), 이름, 이메일, 비밀번호, 비밀번호 확인, 동의 4개 |
| 이름 | 앞뒤 공백을 자른 뒤 2~20자 |
| 이메일 | 공백 제거 → 소문자 → 형식 검사, 254자 이하. 같은 주소는 대소문자와 상관없이 한 계정 |
| 비밀번호 | 8자 이상, 영문과 숫자 포함, UTF-8 72바이트 이하. **앞뒤 공백도 비밀번호의 일부** (자르지 않음) |
| 비밀번호 확인 | 비밀번호와 같아야 함 — "비밀번호가 서로 달라요." |
| 동의 | 만 14세 이상 / 이용약관 / 개인정보 수집·이용 / 민감정보 수집 모두 필수 — "필수 항목에 모두 동의해 주세요." |
| 처리 | 선택한 역할의 프로필만 만든다. `termsVersion`·`termsAgreedAt` 기록 |
| 제한 | IP 당 1시간 10회 |
| 이미 가입한 이메일 | "이미 가입된 이메일이에요." (동시 가입도 DB unique 로 막아 같은 문구) |
| 가입 후 | 로그인 상태가 되어 회원은 `/home`, 트레이너는 `/trainer` |
| 오류 후 | 입력한 이름·이메일·유형·동의가 유지된다. 비밀번호 칸만 비운다 |

### 1-2. 로그인·세션 (FR-AUTH-04~05)

- 이메일(대소문자 무시) + 비밀번호. 없는 계정에도 같은 시간이 걸리도록 더미 해시를 비교한다
- 실패 문구는 계정 존재 여부를 알려주지 않는다
- 제한: 계정+IP 15분 5회(실패만, 성공하면 비움), IP 15분 20회 — 걸리면 안내 문구를 보여준다
- 세션: JWT 쿠키(7일) + `AuthSession` 행. 로그아웃은 행을 폐기하므로 즉시 무효
- 상태가 `ACTIVE` 가 아닌 계정(탈퇴, 정지, 트레이너가 만든 가입 전 `PENDING`)은 로그인할 수 없다
- 로그인한 사람이 `/login` 에 가면 `/` 로 보내고, `/` 가 역할에 따라 `/home` 또는 `/trainer` 로 보낸다
- 회원 화면에 트레이너가, 트레이너 화면에 회원이 들어오면 각자의 홈으로 돌려보낸다

### 1-3. 비밀번호 재설정 (FR-AUTH-06~07)

1. `/forgot-password` 에서 이메일을 낸다. **가입 여부와 상관없이** "메일을 보냈어요" 류의 같은 안내를 보인다
2. 가입된 이메일이면 재설정 링크 메일을 보낸다. 토큰은 해시만 저장하고 만료가 있다. 새 링크를 받으면 이전 링크는 못 쓴다
3. 링크를 열면 `/reset-password` 에서 새 비밀번호(규칙·확인은 가입과 같음)를 정한다. 링크는 한 번만 쓸 수 있다
4. 바뀌면 그 계정의 모든 로그인이 끊긴다
5. 메일 발송에 실패하면 성공한 것처럼 보이지 않고 실패를 알린다

제한: IP 1시간 10회, 계정 1시간 3회.

### 1-4. 내 정보 수정·탈퇴 (FR-AUTH-09~10)

- 이름(2~20자), 전화번호(선택, 숫자·`+`·`-`·공백·괄호 9~20자). 트레이너는 활동 이름(20자)·전문 분야(60자) 등 소개를 더 적는다
- 비밀번호 변경: 지금 비밀번호가 맞아야 하고, 바꾸면 다른 기기 로그인이 풀린다
- **탈퇴**: 비밀번호를 한 번 더 받는다(트레이너가 만든 계정이라 비밀번호가 없는 회원은 면제)
  - 이름·이메일·전화번호를 지워 익명으로 바꾼다. 사용자 행은 남긴다
  - 혼자 남긴 기록(식단과 사진, 체성분, 목표, 개인 운동, 즐겨찾기, 알림)은 삭제한다
  - 트레이너와 함께 만든 기록(계약·회차·알림장·댓글)은 상대의 업무 기록이라 이름만 지우고 남긴다
  - 아직 안 한 수업은 차감 없이 취소한다
  - 트레이너는 **진행 중이고 횟수가 남은 계약이 있으면** 탈퇴할 수 없다 — 계약을 먼저 마무리한다

## 2. 트레이너–회원 연결 (FR-CON)

| 방법 | 흐름 | 규칙 |
| --- | --- | --- |
| 가입 전 회원 만들기 (FR-CON-01) | 트레이너: 회원 → 회원 추가 → 이름(+연락처) | 이름 1~20자, 같은 트레이너 밑에서 중복 불가("이미 ○○ 회원이 있어요…"), 연락처 형식 검사("전화번호는 숫자와 - 만 써서 입력해주세요."). 상태 `PENDING` 인 사용자와 연결이 함께 만들어진다 |
| 이어받기 (FR-CON-02) | 트레이너가 회원 상세에서 이어받기 링크 발급 → 회원에게 전달 → 회원이 링크에서 가입 | 링크 유효 14일. 새 링크를 만들면 이전 링크는 닫힌다. 링크로 가입하면 이름은 고정, 이메일·비밀번호를 정하고 기존 계약·수업·기록이 그대로 이어진다. 이미 가입한 회원이면 "이미 가입한 회원이에요…", 쓸 수 없는 링크는 "쓸 수 없는 링크예요. 트레이너에게 새 링크를 받아 주세요." |
| 초대 코드 (FR-CON-03) | 트레이너: 내 정보 → 코드 만들기 → 회원에게 전달 → 회원: 내 정보 → 코드 입력 | 기본 유효 30일(1~90일), 최대 50명. 만료/소진/본인 코드/이미 연결/다른 트레이너와 연결 중은 각각 안내("만료된 코드예요." "다 쓴 코드예요." "내 코드는 넣을 수 없어요." "이미 연결된 트레이너예요."). 코드는 취소할 수 있다 |
| 한 번에 한 트레이너 (FR-CON-06) | 회원: 담당 트레이너가 있는 상태에서 다른 트레이너 코드 입력 | 거절하고 "이미 담당 트레이너(○○)가 있어요. 트레이너를 바꾸려면 먼저 내 정보에서 연결을 끊어 주세요." 로 안내한다. 거절된 코드는 사용 횟수에 잡히지 않는다. 두 코드를 동시에 넣어도 한쪽만 연결된다. 같은 트레이너 코드를 다시 넣으면 기존처럼 "이미 연결된 트레이너예요." |
| 끊기 (FR-CON-04) | 회원: 내 정보 → 트레이너 연결 끊기 | 연결이 `ENDED` 가 되고 트레이너는 그 회원의 공유 항목을 더 못 본다. 지난 계약·수업·알림장은 남는다 |

- **정책: 한 회원 한 트레이너.** 공유 설정이 회원에게 하나뿐이고 트레이너 화면이 한 명 기준이라, 둘을 허용하면 식단 등이 의도치 않게 두 사람에게 열린다. 베타에서는 막고, 필요해지면 공유 설정을 트레이너별로 나눈 뒤 푼다
- 초대 코드는 **회원이 입력해야** 연결된다. 코드를 만든 것만으로는 연결 회원이 없다
- 트레이너 시작하기 카드(FR-CON-05): 회원 연결 → PT 계약 → 첫 수업 → 알림장 게시, 네 단계가 끝나면 사라진다.
  1단계의 주 버튼은 "회원 추가하기", 초대 코드는 보조 링크이며 만들어 둔 상태면 이유를 설명한다

## 3. PT 계약 (FR-PT-01~02, 05)

| 항목 | 규칙 |
| --- | --- |
| 만들기 | 트레이너가 담당(ACTIVE) 회원에게 만든다 |
| 횟수 | 1~300 정수 — "횟수는 1회부터 300회까지 넣을 수 있어요." |
| 이름 | 비우면 "PT n회". 60자 이하 |
| 기간 | 시작일 필수, 만료일 선택(없으면 무기한). 2000~2100년, 만료일은 시작일 이후 — "만료일이 시작일보다 앞서요." |
| 센터 | 선택. 내가 활동 중인 센터여야 한다 |
| 상태 | `ACTIVE` → `COMPLETED`(횟수 소진, 되돌리면 다시 `ACTIVE`) / `EXPIRED`(기간 지남) / `CANCELLED`(중단) |
| 만료 | 상태를 바꾸지 않고 **읽을 때 기간을 함께 본다**(`expired`). 기간을 연장하면 만료로 닫힌 계약이 다시 열린다 |
| 중단 | 남은 회차는 그대로 두고 상태만 `CANCELLED`. 아직 안 한 수업은 차감 없이 함께 취소 |
| 오류 표시 | 폼 실패는 주소 코드(`?error=`)로만 전달하고 문구는 화면이 고른다 — "입력한 값을 확인해주세요." 등 |

남은 횟수 = 총 횟수 − 차감된 회차(`deducted = true`) 수. 차감 수는 수업 상태가 바뀔 때마다 다시 센다(`syncUsedSessions`).

## 4. 수업 (FR-PT-03~08)

### 4-1. 수업 잡기

- 진입: 일정 화면의 "수업 추가", 회원 계약 상세, 수업 완료 후 "다음 수업"
- 입력: 계약(회원), 날짜, 시각, 진행 시간(10~240분 정수, 기본 60), 메모(200자 이하). 날짜는 2000~2100년
- 진행 중(ACTIVE) 계약만 가능 — "진행 중인 계약이 아니에요."
- **차감된 수업 + 예정 수업이 총 횟수에 이르면** 더 잡을 수 없다 — "남은 횟수가 없어요. 횟수나 기간을 먼저 확인해주세요." 취소·노쇼(차감 안 함)로 빠진 수업은 세지 않는다
- 회차 번호는 계약 안에서 잡은 순서(겹치지 않기만 하면 됨). 같은 계약 동시 예약은 잠금으로 줄 세운다
- 잡으면 회원 화면의 해당 수업에 변경 표시(`memberAlertAt`)가 붙는다. 알림 목록(푸시)으로는 보내지 않는다 — 수업 24시간 전 알림(8장)이 대신한다
- 서랍/패널에서 실패해도 입력한 회원·날짜·시각이 유지된다

### 4-2. 수업 상태

```
SCHEDULED ──완료──▶ COMPLETED   (차감: 항상)
    │      ──노쇼──▶ NO_SHOW     (차감: 고름, 기본 아니오)
    │      ──취소──▶ CANCELLED   (차감: 고름, 기본 아니오)
    ▲                  │
    └──── 예정으로 되돌리기 ◀──┘   (운동 기록이 붙은 수업은 되돌릴 수 없음)
SCHEDULED ──미루기──▶ SCHEDULED  (시각만 변경, 이력 `PTSessionReschedule` 에 누가·언제에서 언제로)
```

| 동작 | 회원 알림 | 비고 |
| --- | --- | --- |
| 수업 추가 | 없음(변경 표시만) | 회원 화면에 새 수업 표시 |
| 미루기 | "PT 일정이 변경되었어요" | 같은 시각이면 "같은 시각이에요." 끝난 수업은 "이미 끝난 수업이에요." |
| 완료 | 없음 | 회원은 그 자리에 있었다. 변경 표시를 내린다 |
| 노쇼 | "PT 수업 상태가 변경되었어요" | 차감 선택 |
| 취소 | "PT 수업이 취소되었어요"(+사유) | 차감 선택. 취소한 사람(트레이너/회원)과 사유를 기록 |
| 되돌리기 | "PT 수업이 다시 예약되었어요" | 차감이 풀리고 계약이 다시 열릴 수 있다 |

- 이미 처리한 수업을 다시 처리하려 하면 "이미 처리한 수업이에요. 되돌린 뒤에 다시 해주세요."
- 수업 완료 직후 "다음 수업 잡기" 시트가 뜬다. 날짜는 직접 고르고, 그날 내 수업 수를 보여준다. "나중에" 로 닫을 수 있다
- 회원은 자기 수업과 남은 횟수를 **볼 수만** 있다. 변경된 수업의 표시를 눌러 확인(`acknowledge`)하면 표시가 내려간다

### 4-3. 일정 보기 (FR-PT-07)

트레이너 `/trainer/schedule`: 주/월 보기, 날짜 이동, 고른 날의 수업 목록과 "수업 추가". 그날 마지막 수업 다음 시각을 기본 시각으로 채운다.

## 5. 수업 기록·알림장 (FR-JNL)

### 5-1. 수업 기록 (`/trainer/sessions/[id]`)

- 수업 전 브리핑(지난 수업 기록, 요약)과 수업 중 운동 추가, 세트(무게·횟수) 입력
- 지난 수업의 운동을 복사할 수 있다. 세트 추가·완료·수정·삭제는 즉시 화면에 반영하고 실패하면 되돌리고 알린다
- 기록의 주인은 회원이다. `recordedByUserId` 로 트레이너가 적은 것임을 남긴다. 수업 기록은 공유 설정과 무관하게 회원이 본다
- 수업 마무리(완료/노쇼/취소/되돌리기)는 이 화면의 모달에서 한다
- 운동 기록을 비울 수 있다(운동 기록이 있는 수업은 되돌릴 수 없으므로 먼저 비운다)

### 5-2. 알림장 (FR-JNL-03~05)

| 항목 | 규칙 |
| --- | --- |
| 시작 | 트레이너가 회원(과 선택 수업)을 골라 초안을 만든다 |
| 칸 | 제목(100자), **내용(필수, 5000자)**, 운동 요약·식단 안내·주의·다음 목표(각 2000자). 칸 길이는 입력 제한이고, 내용이 5000자를 넘으면 잘라 저장하지 않고 "내용이 너무 길어요. 5000자 이하로 줄여 주세요." |
| 사진 | 최대 10장, 장당 5MB, 올리면서 줄여 저장(원본+썸네일), 경로 형식 검증 |
| 게시 | 내용이 비면 "내용을 적어주세요." 게시하면 회원에게 "새 알림장이 도착했어요" 알림. **처음 게시할 때만** 알린다 |
| 수정 | 게시 후에도 고칠 수 있다(댓글 보존). 초안으로 되돌리지는 않는다 |
| 삭제 | 초안만 삭제할 수 있다 |
| 실패 | 게시/저장이 실패해도 쓴 글이 지워지지 않는다 |
| 읽음 | 회원이 열면 `memberReadAt` 기록. 트레이너 화면에서는 읽었는지를 따로 강조하지 않는다 |
| 댓글 | 회원↔트레이너 모두 달 수 있다. 회원이 달면 트레이너에게 "회원 댓글이 달렸어요", 트레이너가 달면 회원에게 "알림장에 댓글이 달렸어요" |

트레이너 `/trainer/journals`("할 일" 탭)는 완료 처리할 수업과 쓸 알림장을 모아 보여준다.

## 6. 회원 기록

### 6-1. 운동 (FR-WKT)

- 라이브러리: 부위·기구·난이도·운동 방식으로 검색, 상세(방법·호흡·주의·필요한 기구), 즐겨찾기
- 실시간 기록(`LIVE`): 시작 → 운동 추가 → 세트 입력 → 종료. 진행 중인 기록은 홈에서 이어 한다. **진행 중 실시간 기록은 한 번에 하나**
- 몰아서 기록(`MANUAL`): 날짜를 골라 지난 운동을 입력한다. 같은 날짜의 작성 중 기록은 재사용하고, 저장한 기록은 재사용하지 않는다(하루 두 번 운동 가능). 운동 시간(1~1440분)은 선택
- 세트: 중량 0~1000, 횟수 0~1000 정수, 휴식 0~3600초, RPE 1~10, 메모 300자. 운동 메모 500자
- **운동 시간(FR-WKT-05)**: 운동 중에는 상단에 스톱워치처럼 `12:34`(1시간 넘으면 `1:02:15`)가 1초마다 흐른다. 아래 "시간" 칸은 "진행 중"으로 둔다
  - 끝낼 때 자동 계산: 마지막으로 운동·세트를 적은 뒤 20분 안이면 지금까지, 더 지났으면 마지막 기록 + 5분까지만 잰다(끝내기를 잊고 나중에 눌러도 부풀지 않는다). 기록이 하나도 없으면 시작 + 4시간을 넘기지 않는다
  - 요약 화면에서 "시간이 다르면 고치기"로 분 단위(1~1440)로 고친다. 몰아서 기록해 시간이 없으면 "운동 시간 적기". 수업(PT)에서 트레이너가 적어 준 기록은 고칠 수 없다
- 요약: 총 볼륨 등. 운동별 추이 그래프

### 6-2. 식단 (FR-DIET)

- 날짜, 끼니(아침·점심·저녁·간식·기타), 음식 이름, 메모, 사진(선택)
- **사진도 글도 없으면** "사진을 올리거나 무엇을 먹었는지 적어주세요."
- 사진은 등록 전에 사용자 폴더(`diets/{userId}/…`)로 올리고, 등록하지 않고 나가면 정리한다. 다른 사람 폴더 경로는 받지 않는다
- 기록은 지울 수 있다(사진도 저장소에서 함께 삭제)
- 트레이너 피드백: 공유된 식단에 글을 남기고 지울 수 있다. 남기면 회원에게 "식단 피드백이 도착했어요". 공유가 꺼져 있으면 쓸 수 없다("공유하지 않았어요")

### 6-3. 체성분·목표 (FR-BODY)

| 항목 | 범위 |
| --- | --- |
| 체중 | 범위 검사 후 소수 한 자리로 반올림 |
| 체지방률 | 1~70 % |
| 골격근량 | 5~100 kg |
| 허리둘레 | 30~200 cm |
| 메모 | 300자 |

- 날짜는 오늘까지만("아직 오지 않은 날은 적을 수 없어요."), 하나도 안 채우면 "적어도 하나는 채워주세요."
- 같은 날짜(`recordedAt`)는 한 사용자에 한 건
- 목표: 종류(체중·체지방·근육량·운동 빈도·PR·직접 입력), 목표 값(필수), 목표 날짜, 시작 값. 취소할 수 있다

## 7. 공유 (FR-SHR)

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| 식단 | 켜짐 | 트레이너가 식단 목록·상세를 본다 |
| 식단 사진 | 켜짐 | 식단이 켜져 있어야 의미가 있다. 서버가 `식단 && 사진` 으로 맞춘다 |
| 개인 운동 | 꺼짐 | 혼자 한 운동 기록 |
| 체성분 | 꺼짐 | 체중·체지방·근육량 |
| PT 수업 기록 | (설정 없음) | 항상 공유 — 트레이너가 적은 기록이다 |

- 설정 행은 미리 만들지 않고, 없으면 기본값을 쓴다. 담당 트레이너가 없어도 화면은 열린다
- **트레이너가 회원 데이터를 읽는 길은 하나**(`assertTrainerCanView`): ① 트레이너 프로필이 있는가 ② 내 담당(ACTIVE) 회원인가 ③ 그 항목을 공유했는가. 앞의 둘이 아니면 "없는 사람"(404)으로 답해 존재를 알리지 않고, 마지막만 "회원이 공유하지 않았어요" 라고 말한다
- 관계가 시작된 날 이전 기록은 트레이너에게 보이지 않는다(알려진 예외: 04 문서 "알려진 한계")

## 8. 알림 (FR-NTF)

| 종류 | 받는 사람 | 발생 | 푸시 카테고리 |
| --- | --- | --- | --- |
| `JOURNAL_CREATED` | 회원 | 알림장 최초 게시 | 새 알림장 |
| `PT_SESSION_CHANGED` | 회원 | 수업 미루기·노쇼·취소·되돌리기 | 수업 변경 |
| `PT_SESSION_REMINDER` | 회원·트레이너 | 매일 09:00 KST, 24시간 안의 예정 수업 | 수업 알림 |
| `PT_CONTRACT_EXPIRING` | 회원·트레이너 | 매일 09:00 KST, 만료 3일 안 또는 남은 횟수 1~2회 | 이용권 안내 |
| `GENERAL` | 회원·트레이너 | 식단 피드백, 알림장 댓글 | 댓글·기타 |

- 같은 대상(받는 사람·종류·관련 객체)에 이미 알림이 있으면 매일 알림은 다시 만들지 않는다. `PENDING` 회원에게는 보내지 않는다
- 푸시는 홈 화면에 추가한 앱(iOS)에서 동작한다. 종류별로 끌 수 있고, 꺼도 앱 안 알림은 쌓인다. 푸시 설정은 Firebase 값이 있어야 보인다
- 알림을 누르면 읽음 처리하고 관련 화면으로 이동한다. "모두 읽음" 이 있다
- 매일 알림은 Vercel Cron 이 `/api/cron/reminders` 를 `CRON_SECRET` 으로 부른다. 시크릿이 없거나 틀리면 401
