# 05. 테스트 시나리오

세 층으로 확인한다. "자동" 칸은 이미 있는 테스트의 위치다. 비어 있으면 **자동 테스트가 없는 항목**이니 수동으로 본다.

| 층 | 위치 | 실행 | 비고 |
| --- | --- | --- | --- |
| 단위 | `tests/*.test.ts` (vitest) | `npm test` | 스키마·계산 |
| 통합 | `tests/integration/*.itest.ts` | `npm run test:integration` | 임시 Postgres 를 띄움. 운영 DB 는 건드리지 않음 |
| E2E | `e2e/*.spec.ts` (Playwright, Chromium) | `npm run test:e2e` | 실제 화면. 아이폰 Safari 는 포함되지 않음 |

기준일 E2E 40개 통과. 표기: **E** = e2e, **I** = 통합, **U** = 단위.

## 7. 베타 전 수동 점검표 (실기기)

자동 테스트가 못 보는 것들이다. **아이폰 Safari 와 홈 화면에 추가한 앱** 둘 다에서 본다.

- [ ] 트레이너 새 계정으로 가입 → 시작하기 카드 → 회원 추가 → 계약 → 수업 → 수업 기록 → 완료 → 알림장 게시를 처음부터 끝까지
- [ ] 위 회원 계정으로 이어받기 링크 가입 → 알림장·내 PT 에 기록이 보이는지
- [ ] 수업 추가의 날짜·시간 칸이 칸을 넘치지 않고 글자가 가운데 줄에 맞는지
- [ ] 가입 화면에서 동의를 체크하고 일부러 실패시킨 뒤 체크가 유지되는지(비밀번호 확인을 다르게)
- [ ] 홈 화면 아이콘이 새 덤벨 모양인지(예전 아이콘이면 삭제 후 Safari 에서 다시 추가)
- [ ] 푸시: 알림장 게시, 댓글, 수업 변경이 회원 폰에 오는지(홈 화면에 추가한 앱에서만)
- [ ] 긴 한국어 문장(빈 상태 안내 등)이 단어 중간에서 끊기지 않는지
- [ ] 비밀번호 재설정 메일이 도착하고(스팸함 포함) 링크가 열리는지
- [ ] 회원 탈퇴 후 같은 이메일로 다시 가입이 되는지(되어야 하는지 정책 확인)
- [ ] 약관·처리방침의 운영자·문의처가 실제 연락 가능한 정보인지
- [ ] Supabase 수동 백업을 한 번 받아 두었는지

## 8. 알려진 공백 (자동 테스트가 없는 영역)

- 회원 쪽 입력 검사(식단·운동·체성분 외 화면)의 극단값 점검
- 푸시 실제 수신, 아이폰 Safari 화면
- 수업 노쇼/되돌리기/미루기의 E2E (통합 테스트로는 차감·취소만 있음)
- 동시성: 같은 계약에 동시에 수업 잡기(잠금은 구현되어 있으나 전용 테스트 없음)
