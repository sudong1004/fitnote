# 01. 요구사항 정의서

## 1. 서비스 개요

**FitNote** 는 PT 트레이너와 회원을 위한 **운동 기록 + PT 알림장 + 수업·이용권 관리** 웹앱이다(PWA, 모바일
우선). 트레이너가 회원과 수업을 관리하고 수업 내용을 기록하면, 그 내용이 회원의 운동 기록과 알림장으로
이어진다. 회원은 혼자 하는 운동·식단·체성분도 기록하고, 원하는 만큼만 트레이너에게 공유한다.

### 1-1. 해결하려는 문제

| 문제 | FitNote 의 답 |
| --- | --- |
| 트레이너가 수업·횟수를 수첩이나 메신저로 관리해 남은 횟수가 틀어진다 | 계약(횟수·기간)과 회차를 앱에서 관리하고 완료·노쇼·취소 때 차감을 반영한다 |
| 수업 후 알림장을 메신저에 따로 써서 회원 기록과 이어지지 않는다 | 수업 기록(무게·횟수)과 알림장이 한 흐름이고 회원 운동 기록으로 남는다 |
| 회원이 식단·몸 변화를 올려도 트레이너가 못 보거나 반대로 다 노출된다 | 항목별로 회원이 공유 여부를 정한다 |
| 회원이 다음 수업·변경을 놓쳐 노쇼가 난다 | 일정 알림, 변경 알림, 푸시 |

### 1-2. 사용자(역할)

| 역할 | 설명 | 가입 |
| --- | --- | --- |
| 회원 | 운동·식단·체성분을 기록하고 알림장을 받는다. 트레이너 없이도 쓸 수 있다 | 직접 가입 또는 트레이너가 만든 계정 이어받기 |
| 트레이너 | 회원·계약·수업·알림장을 관리한다. 센터에 소속되지 않아도 된다 | 직접 가입(트레이너 선택) |
| 센터 관리자 | 데이터 모델만 있고 **화면은 아직 없다** | — |

한 계정은 한 역할만 가진다.

### 1-3. 현재 단계

지인 베타 준비 중이다. 트레이너 몇 명과 그 회원이 실제로 쓰는 것을 목표로 하며, 유료화는 베타 이후다.

## 2. 기능 요구사항

우선순위: **필수**(베타 전 반드시) / **권장** / **후순위**. 상태: ✅ 구현 / ⚠ 일부 / ⬜ 미구현.

### 2-1. 계정·인증 (AUTH)

| ID | 요구사항 | 우선 | 상태 |
| --- | --- | --- | --- |
| FR-AUTH-01 | 이메일·비밀번호로 가입한다. 가입 때 회원/트레이너를 고른다 | 필수 | ✅ |
| FR-AUTH-02 | 비밀번호는 두 번 입력해 확인하고 규칙(8자 이상, 영문+숫자, 72바이트 이하)을 지켜야 한다 | 필수 | ✅ |
| FR-AUTH-03 | 이용약관·개인정보·민감정보·만 14세 이상에 모두 동의해야 가입된다. 동의한 판을 기록한다 | 필수 | ✅ |
| FR-AUTH-04 | 이메일·비밀번호로 로그인하고, 로그아웃하면 바로 무효가 된다 | 필수 | ✅ |
| FR-AUTH-05 | 로그인·가입·이어받기 시도 횟수를 제한한다 | 필수 | ✅ |
| FR-AUTH-06 | 비밀번호를 잊으면 이메일로 재설정 링크를 받는다. 가입 여부는 드러나지 않는다 | 필수 | ✅ |
| FR-AUTH-07 | 비밀번호를 바꾸면 다른 기기의 로그인이 풀린다 | 권장 | ✅ |
| FR-AUTH-08 | 가입한 이메일이 본인 것인지 확인한다(이메일 인증) | 권장(공개 출시 전 필수) | ⬜ |
| FR-AUTH-09 | 내 정보(이름·전화번호, 트레이너 소개)를 수정한다 | 필수 | ✅ |
| FR-AUTH-10 | 회원 탈퇴. 비밀번호를 확인하고 개인정보를 지운다 | 필수 | ✅ |

### 2-2. 트레이너–회원 연결 (CON)

| ID | 요구사항 | 우선 | 상태 |
| --- | --- | --- | --- |
| FR-CON-01 | 트레이너가 이름(과 선택 연락처)만으로 가입 전 회원을 만든다 | 필수 | ✅ |
| FR-CON-02 | 가입 전 회원에게 이어받기 링크를 주면, 회원이 가입하며 기존 기록을 이어받는다 | 필수 | ✅ |
| FR-CON-03 | 트레이너가 초대 코드를 만들고, 가입한 회원이 코드를 입력해 연결한다 | 필수 | ✅ |
| FR-CON-04 | 회원이 연결을 끊을 수 있다. 끊어도 기존 기록은 남는다 | 권장 | ✅ |
| FR-CON-05 | 트레이너 첫 사용을 안내하는 시작하기 카드(회원→계약→수업→알림장) | 권장 | ✅ |

### 2-3. PT 계약·수업 (PT)

| ID | 요구사항 | 우선 | 상태 |
| --- | --- | --- | --- |
| FR-PT-01 | 회원에게 PT 계약(횟수, 기간, 이름)을 만든다 | 필수 | ✅ |
| FR-PT-02 | 계약 기간을 연장하고, 계약을 중단한다 | 필수 | ✅ |
| FR-PT-03 | 수업을 잡고(날짜·시간·진행 시간·메모), 미루고, 취소한다 | 필수 | ✅ |
| FR-PT-04 | 수업이 끝나면 완료·노쇼·취소 중 고르고, 노쇼·취소는 차감 여부를 고른다. 되돌릴 수 있다 | 필수 | ✅ |
| FR-PT-05 | 횟수를 다 쓰면 계약이 스스로 닫히고, 되돌리면 다시 열린다 | 필수 | ✅ |
| FR-PT-06 | 수업을 완료하면 바로 다음 수업을 잡을 수 있다 | 권장 | ✅ |
| FR-PT-07 | 트레이너가 일정을 주/월로 본다 | 필수 | ✅ |
| FR-PT-08 | 회원이 자기 수업 일정과 남은 횟수를 본다. 변경된 수업은 확인 표시를 한다 | 필수 | ✅ |
| FR-PT-09 | 회원이 직접 수업을 예약·변경·취소한다 | 후순위 | ⬜ (회원은 보기만 한다) |

### 2-4. 수업 기록·알림장 (JNL)

| ID | 요구사항 | 우선 | 상태 |
| --- | --- | --- | --- |
| FR-JNL-01 | 수업 중 트레이너가 운동·세트(무게·횟수)를 기록하고, 지난 수업 운동을 복사한다 | 필수 | ✅ |
| FR-JNL-02 | 수업 기록은 회원의 운동 기록으로 남는다(공유 설정과 무관) | 필수 | ✅ |
| FR-JNL-03 | 트레이너가 알림장을 쓰고(초안 저장, 사진 최대 10장), 게시하면 회원에게 알림이 간다 | 필수 | ✅ |
| FR-JNL-04 | 게시한 알림장도 고칠 수 있다. 초안으로 되돌리지는 않는다 | 권장 | ✅ |
| FR-JNL-05 | 회원이 알림장을 읽고 댓글을 달고, 트레이너가 답한다. 서로 알림이 간다 | 권장 | ✅ |
| FR-JNL-06 | 센터 공지를 본다 | 후순위 | ⚠ (읽기만. 쓰는 화면 없음) |

### 2-5. 회원 기록 (WKT·DIET·BODY)

| ID | 요구사항 | 우선 | 상태 |
| --- | --- | --- | --- |
| FR-WKT-01 | 운동 라이브러리를 부위·기구·난이도로 찾고 즐겨찾기한다 | 필수 | ✅ |
| FR-WKT-02 | 운동을 실시간으로 기록하거나, 지난 날짜에 몰아서 기록한다 | 필수 | ✅ |
| FR-WKT-03 | 끝난 기록의 요약(볼륨 등)과 운동별 추이를 본다 | 권장 | ✅ |
| FR-WKT-04 | 캘린더에서 날짜별 운동·식단을 본다 | 권장 | ✅ |
| FR-DIET-01 | 끼니별로 사진·글을 남기고 지운다 | 필수 | ✅ |
| FR-DIET-02 | 공유한 식단에 트레이너가 피드백을 남기고 회원에게 알림이 간다 | 권장 | ✅ |
| FR-BODY-01 | 체중·체지방률·골격근량·허리둘레를 기록하고 추이를 본다 | 권장 | ✅ |
| FR-BODY-02 | 체성분 목표를 정하고 진행을 본다 | 후순위 | ✅ |

### 2-6. 공유·알림 (SHR·NTF)

| ID | 요구사항 | 우선 | 상태 |
| --- | --- | --- | --- |
| FR-SHR-01 | 회원이 식단/식단 사진/개인 운동/체성분을 항목별로 트레이너에게 공유할지 정한다 | 필수 | ✅ |
| FR-SHR-02 | 트레이너는 담당 회원의 공유된 항목만 볼 수 있다. 담당이 아닌 회원은 존재도 알 수 없다 | 필수 | ✅ |
| FR-SHR-03 | 트레이너가 회원의 여정(함께한 기간의 변화)을 본다 | 후순위 | ✅ |
| FR-NTF-01 | 앱 안 알림 목록과 읽음 처리 | 필수 | ✅ |

## 3. 비기능 요구사항 (NFR)

| ID | 요구사항 | 현재 |
| --- | --- | --- |
| NFR-01 | 모바일 우선 화면(아이폰 Safari·홈 화면 앱 포함) | 반영. 실기기 확인은 수동 |
| NFR-02 | 비밀번호는 bcrypt 해시, 세션은 JWT + DB 세션 행(로그아웃 즉시 무효), 유효 7일 | 반영 |
| NFR-03 | 권한은 서버(서비스)에서 매번 확인한다. 화면 숨김에 의존하지 않는다 | 반영(04 참고) |
| NFR-04 | 날짜 경계는 KST | 반영 |
| NFR-05 | 서버 지역은 DB 와 같은 도쿄(`hnd1`) | 반영 |
| NFR-06 | 사진은 비공개 저장소에 두고 서명 주소로만 보여준다 | 반영 |
| NFR-07 | 입력은 서버에서 검증하고 한국어 오류 문구를 보여준다. 오류 화면(500)이 뜨지 않는다 | 트레이너 흐름·가입 점검 완료. 회원 쪽은 점검 예정 |
| NFR-08 | 자동 테스트: 단위·통합(임시 Postgres)·E2E(Playwright, Chromium) | 반영(05 참고) |
| NFR-09 | 운영 DB 정기 백업 | 수동(Supabase). 정책 미정 |
| NFR-10 | 메일 발송 한도 | Gmail SMTP 사용 중이라 한도가 낮다. 사용자가 늘면 도메인 메일로 이전 |

## 4. 범위 밖 (지금은 하지 않는 것)

- 결제·정산·구독 (수익 모델 미정)
- 센터 관리자 화면, PT 상품·가격 관리, 센터 기구 프리셋 (데이터 모델만 있음)
- 회원이 직접 수업 예약·취소
- AI 식단·운동 분석 (`AiAnalysis` 테이블만 자리 확보)
- 웹소켓 기반 실시간 통신 (알림은 푸시와 앱 안 목록으로 충분)
- 네이티브 앱 (PWA 로 대신)
